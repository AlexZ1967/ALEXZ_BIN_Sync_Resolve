# ALEXZ_BIN_Sync_Resolve

Bin Sync — самостоятельный скрипт для DaVinci Resolve Studio. Он связывает папку на диске с одноимённым bin в открытом проекте. При каждом запуске он сравнивает обе стороны с состоянием после предыдущей синхронизации. В этой версии синхронизация запускается вручную. Скрипт рассчитан на Linux и Windows с DaVinci Resolve Studio 21.1.2, UIManager и встроенным Python. Windows ещё предстоит проверить в Resolve.

## Установка и запуск

### Linux

Выполни команды из корня репозитория.

```bash
mkdir -p ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility
cp 'Bin Sync.py' ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility/
```

### Windows (PowerShell)

Открой PowerShell в папке, куда хочешь загрузить репозиторий. Если он уже клонирован, выполни `git pull` в его корне и повтори три команды установки.

```powershell
git clone https://github.com/AlexZ1967/ALEXZ_BIN_Sync_Resolve.git
Set-Location ALEXZ_BIN_Sync_Resolve
$binSyncMenu = Join-Path $env:APPDATA 'Blackmagic Design/DaVinci Resolve/Support/Fusion/Scripts/Utility'
New-Item -ItemType Directory -Path $binSyncMenu -Force | Out-Null
Copy-Item -LiteralPath './Bin Sync.py' -Destination $binSyncMenu -Force
```

На обеих системах скрипт открывается через **Workspace → Scripts → Utility → Bin Sync**. Если после первой установки команда не появилась, открой Resolve заново.

При обновлении скопируй скрипт поверх прежней пользовательской копии. Сохранённые привязки на той же системе подхватятся автоматически. При открытии проекта на другой системе создай привязку к её локальному пути.

### Управление привязками

- **Новый bin из папки.** Выбери корень Media Pool, открой **Workspace → Scripts → Utility → Bin Sync** и оставь в списке **Новая привязка**. Укажи папку на диске и нажми **Показать изменения**. Скрипт предложит создать bin с именем папки. Если одноимённый bin уже есть, можно выбрать его в Media Pool и заново открыть скрипт.
- **Привязать существующий bin.** Выбери его в Media Pool и открой скрипт. Если привязки нет, укажи папку. В плане будут добавления с обеих сторон, если bin и папка уже содержат медиа.
- **Обновить привязку.** Выбери связанный bin или любой его подбин перед запуском скрипта. В окне появится путь привязанной папки. Из корня Media Pool любую сохранённую пару можно выбрать в выпадающем списке. Просмотри план и нажми **Применить и сохранить проект**.
- **Отключить привязку.** Открой её через bin или список в корне, нажми **Отключить привязку**, затем **Подтвердить отключение**. Bin, клипы, файлы и папка восстановления останутся на месте. Этот bin можно привязать снова.

В одном проекте можно хранить несколько пар. У каждой своё состояние и журнал. Скрипт автоматически подхватывает привязку, созданную предыдущей версией. Привязки в одном проекте должны охватывать разные деревья: папку или bin, уже входящие в другую привязку, нельзя привязать отдельно. Перенос уже связанных объектов между разными привязками останавливается как конфликт.

## Какие изменения переносит скрипт

| Изменение | Результат с другой стороны |
| --- | --- |
| На диске появился медиафайл или подкаталог | Импортирует клип или создаёт подбин, включая пустые папки |
| Файл или папку переместили на диске | Переносит существующие клипы или подбины и обновляет пути к исходникам |
| Создали подбин или импортировали в него файл | Создаёт папку или копирует исходник в неё, затем подключает данный клип к копии. Исходник остаётся на месте |
| Клип или подбин переместили внутри привязки | Перемещает файл или папку на диске и обновляет пути к исходникам |
| Удалили файл с диска | Удаляет клип из bin. При обнаружении прямого использования на таймлайне останавливает применение |
| Удалили клип в bin | Перемещает файл на том же диске в скрытую папку `.resolve-bin-sync-recovery` внутри привязки |
| Удалили подбин или подкаталог | Разбирает изменения дочерних элементов, затем убирает опустевшую папку с другой стороны |

На диске распознаются обычные медиафайлы с расширениями из списка в скрипте. Реальную поддержку каждого формата определяет Resolve. PNG, JPEG, TIFF, EXR и DPX синхронизируются по одному файлу, включая имена с номером кадра. Если Resolve группирует нумерованные картинки, включи **Show Individual Frames** в меню **Media Storage** на странице **Media** и повтори импорт. Сгруппированные последовательности не синхронизируются как один объект. Скрытые файлы и символические ссылки пропускаются. Таймлайны, генераторы и другие элементы без обычного исходного файла находятся вне привязки. При обнаружении посторонних элементов в удаляемой папке скрипт остановится. Перемещение папки на диске затрагивает всё её содержимое.

Скрипт распознаёт переносы в пределах одного тома. Если назначение уже занято, объект вынесен из привязанного bin или один объект перемещён по-разному с обеих сторон, он показывает конфликт. Рабочая модель — локальный проект с одним редактором. Дождись завершения записи новых медиафайлов и оставь папку и bin без параллельных изменений на время применения.

Переименование подбина переносится на диск. При переименовании папки на диске Resolve создаёт новый подбин и переносит туда содержимое, поскольку в установленном API у Folder нет операции переименования. При смене имени исходного файла используется `ReplaceClipPreserveSubClip`. При изменении только каталога используется `RelinkClips`. Переименование отображаемого имени клипа в Resolve не меняет имя файла. Сохранность метаданных и монтажных ссылок при перелинковке подлежит ручной приёмке.

## Если применение прервалось

Изменения в файловой системе и Resolve выполняются отдельными операциями. При ошибке применение останавливается, а окно показывает путь к журналу `*.pending.json`. Он содержит исходный план и путь к папке восстановления. Выполненные шаги видны по строкам `[Bin Sync]` в **Workspace → Console**. Если первый запуск только создавал bin и добавлял медиа, снова открой скрипт в том же проекте и нажми **Показать изменения**. Скрипт найдёт bin по ID и предложит продолжить импорт. В остальных случаях верни диск и bin к состоянию до прерванного применения, затем убери журнал из папки состояния.

Если Resolve не принял отдельный файл и целевой bin остался без изменений, скрипт продолжит импорт остальных файлов. Список непринятых файлов появится в окне, ответы API будут в **Workspace → Console**. Следующий запуск предложит импорт этих файлов снова. Один из способов выяснить, принимает ли Resolve конкретный файл, — перетащить его в Media Pool вручную.

В Linux файлы состояния лежат в `$XDG_STATE_HOME/alexz-resolve-bin-sync` или `~/.local/state/alexz-resolve-bin-sync`. В Windows — в `%LOCALAPPDATA%\alexz-resolve-bin-sync`. Рядом с отключённой привязкой создаётся файл `.detached`, а предыдущий снимок остаётся для диагностики. Файлы из папки восстановления можно вернуть вручную. Удаление bin целиком и отключение диска останавливают существующую привязку.

В Windows для первой проверки используй локальную папку на NTFS. Скрипт сопоставляет переносы по ID файлов, поэтому папка должна быть на файловой системе, которая их предоставляет. Junction пропускаются. Если Windows не даёт переместить открытый файл, закрой программу, которая его удерживает, и проверь журнал перед повторным применением.

## Первая ручная приёмка

В отдельном проекте создай папку с двумя подкаталогами и несколькими копиями коротких MOV, MP4 или WAV. Импортируй через Bin Sync и убедись, что повторный запуск показывает «Изменений нет». Затем по одному меняй стороны и проверяй план перед применением.

- На диске перемести файл между папками, перемести подкаталог, добавь и удали обычный медиафайл. Проверь, что перенесённый клип открывается и его **File Path** указывает на новое место.
- В Resolve перемести клип и подбин, создай пустой подбин, добавь файл из другой папки и удали один клип. Проверь новый путь, сохранность внешнего оригинала и содержимое папки восстановления.
- Перемести один клип по-разному с обеих сторон и проверь, что план сообщает о конфликте. Затем проверь удаление файла, клип которого используется на таймлайне.
- В корне Media Pool создай вторую привязку к другой папке. Проверь обе пары из выпадающего списка, открой скрипт из подбина, затем отключи одну привязку и проверь, что вторая по-прежнему доступна, а на диске и в Media Pool ничего не исчезло.
- Добавь три PNG с номерами подряд. В плане должны появиться все три файла, а после применения в bin должны быть три отдельных клипа с точными путями к PNG.
- Отдельно проверь переименование папки и файла на диске и то, что монтажный экземпляр остаётся связанным с нужным медиа после перелинковки.

Синтаксис можно проверить системным Python без подключения к Resolve.

```bash
python3 -m py_compile 'Bin Sync.py'
```

На Windows повтори сценарии с папкой, в имени которой есть пробелы и кириллица, например `D:\Монтаж\Bin Sync`. Проверь перенос файла между подкаталогами, появление удалённого из bin файла в папке восстановления и повторное открытие сохранённой привязки. Дополнительно проверь смену регистра в имени подкаталога и отказ при уже занятом пути назначения.
