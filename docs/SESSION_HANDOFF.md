# Состояние проекта для нового диалога

## Перенос Bin Sync на Windows — 2026-11-20

В одном скрипте добавлены Windows-блокировка через msvcrt, перенос на томе без перезаписи назначения, хранение привязок в LocalAppData и сопоставление путей Resolve с учётом разделителей и регистра каталогов. В Linux сохранены flock, renameat2 и прежнее расположение состояния. README содержит PowerShell-установку и сценарии ручной приёмки для Windows. Установку, проверки и Resolve агент не запускал. Следующий шаг — приёмка пользователем на Windows с локальной папкой NTFS и повтор сценариев на Linux.

## Выделение в самостоятельный проект — 2026-11-20

Исходник Bin Sync и инструкция перенесены из ALEXZ_SilentFilm_OFX в отдельный локальный Git-репозиторий ALEXZ_BIN_Sync_Resolve. Установка выполняется из корня нового репозитория. Формат состояния, путь к файлам привязок и имя команды Bin Sync сохранены. Пользователь подтвердил, что компактный интерфейс выглядит хорошо. Официальный SDK Resolve не предоставляет регистрации команд в контекстном меню bin. После переноса агент не запускал скрипт, Resolve и проверки. Следующий шаг при необходимости — продолжать разработку и ручную приёмку из нового репозитория.

## Bin Sync для Resolve — 2026-11-19

Окно Bin Sync открывается в размере 780 × 340. Строки поля пути и кнопок используют штатный размер, свободная высота отдана плану синхронизации. Компоновка основана на Python-примерах UIManager из установленного SDK. Следующий шаг — открыть обновлённый скрипт и изменить размер окна в Resolve. Агент Resolve не запускал.

Пользователь сообщил о зависании при создании новой привязки. В обработчике выбора найден повторный вызов обновления ComboBox через Clear/AddItem/CurrentIndex. Теперь обработчик выбора обновляет только поля окна, повторные события того же пункта игнорируются. Изменение пути после предпросмотра проверяется при применении. На момент исправления виден только старый файл состояния V2V, нового журнала нет. Обновление в Resolve не запускалось.

Добавлено несколько привязок в одном проекте с отдельными снимками и журналами, выбор по ID текущего bin или его предков, список привязок из корня Media Pool, создание нового bin, подключение существующего и отключение с сохранением файлов и bin. Старый файл V2V читается как отдельная привязка без миграции на диске. Следующая пользовательская проверка — открыть V2V, создать вторую пару из корня, открыть из подбина и отключить вторую пару. Resolve и проверки агент не запускал.

Пользователь подтвердил синхронизацию видео. Для отсутствующих PNG найдена точная причина: `V2V/pics/Gen_00001.png`–`Gen_00003.png` отбрасывались фильтром имён, оканчивающихся цифрой. Фильтр снят. Импорт изображений проверяет путь отдельного файла, а при распознанной группировке показывает подсказку про Show Individual Frames. Обновление для изображений в Resolve ещё не проверялось.

Пользователь подтвердил создание bin, клипы не появились. Локальный журнал подтвердил ID bin и план импорта шести MP4 из V2V. Лог Resolve не показал причину. Скрипт обновлён: три варианта вызова импорта, сверка новых клипов внутри целевого bin, пропуск файлов при отказе без изменений и продолжение прерванного первого импорта в существующий bin по ID. Повторный запуск новой версии остаётся за пользователем.

Подготовлен отдельный пользовательский [скрипт Bin Sync](../README.md) для ручной двусторонней синхронизации папки и bin. Есть предварительный план, сопоставление объектов между запусками, перелинковка при переносе, папка восстановления для файлов и журнал незавершённой операции. Использованы методы из установленного Resolve Scripting API 21.1.2. Синтаксическая проверка, установка и запуск в Resolve не выполнялись. Следующий шаг — пользовательская приёмка в отдельном проекте на копиях медиа по инструкции Bin Sync, в том числе проверка стабильности ID после сохранения и перелинковки клипов на таймлайне.
